# CatLuBooks

RAG-ассистент по документам: ищет ответ в ваших книгах/файлах и отвечает,
ссылаясь на источник и страницу. Веб-интерфейс работает и на ПК, и на телефоне
(как приложение через PWA).

## Как это работает

```
PDF ─► текст ─► фрагменты ─► эмбеддинги ─► векторная база (ChromaDB)
                                              │
вопрос ─► поиск (вектор + точные совпадения) ─┤
                                              ▼
                    контекст + вопрос ─► LLM ─► ответ со ссылками
```

- **Эмбеддинги** считаются локально (модель маленькая, интернет не нужен).
- **Генерация** — через любой OpenAI-совместимый сервер: Ollama, LM Studio,
  llama.cpp, а также облако (OpenAI, OpenRouter, Groq, DeepSeek).

## Возможности

- Индексация PDF пачками, без загрузки всей книги в память.
- Гибридный поиск: векторный + приоритет точных совпадений; к ответу
  добавляются соседние фрагменты и номер страницы PDF.
- Потоковый ответ (текст «печатается» по мере генерации).
- Веб-чат + PWA: ставится на телефон как приложение.
- Всё сменное — в одном файле `config.yaml` (тема, модель, база, промпты).

## Установка

Нужен Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .\.venv\Scripts\activate
pip install -r requirements.txt
```

## Подготовка базы

Положите PDF-файлы в папку `research/`, затем:

```bash
python -c "from config import load_config; from core.store import VectorStore; VectorStore(load_config()).index()"
```

Повторный импорт файла с тем же именем обновляет его фрагменты.

## Запуск

```bash
python app.py
```

- На ПК: <http://localhost:8000>
- С телефона (тот же Wi-Fi): `http://<IP-ПК>:8000` → «Добавить на главный экран».
- Свой IP: `ipconfig` (Windows). При первом запуске разрешите доступ в фаерволе
  для **частных** сетей.

## Настройка (`config.yaml`)

| Блок | Что задаёт |
|---|---|
| `prompt` | тема и поведение ассистента (системный промпт и шаблоны) |
| `store` | путь к базе, коллекция, папка с PDF, размеры фрагментов |
| `embeddings` | локальная модель эмбеддингов |
| `llm` | провайдер, модель, параметры генерации |
| `search` | сколько фрагментов искать, лимит контекста, история, режим поиска |
| `server` | адрес и порт |

**Сменить тему** — только блок `prompt`. **Сменить модель** — `llm.model`.
**Сменить провайдера** — `llm.provider` + переменная окружения `LLM_API_KEY`:

```bash
# пример: облако вместо локальной Ollama
set LLM_API_KEY=sk-...          # Windows
# provider: openai, model: gpt-4o-mini  (в config.yaml)
```

**Только этот ПК, без доступа по сети** — `server.host: 127.0.0.1`.

### Подбор модели под слабое железо

Если GPU слабый (мало VRAM), 8B-модели считаются на CPU и отвечают медленно.
Варианты:

- лёгкие локальные: `qwen2.5:3b`, `gemma2:2b`, `llama3.2:3b`;
- либо генерация в облаке (Groq, Gemini, OpenRouter) — поиск и эмбеддинги
  остаются локальными, в облако уходит только найденный контекст;
- уменьшить `search.n_results` и `search.max_context_chars`, снизить `max_tokens`;
- держать `search.lexical: false` (по умолчанию) — полное сканирование базы
  даёт приоритет точным совпадениям, но на большой базе стоит секунды на запрос.
