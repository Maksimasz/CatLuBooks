## 1. Что это такое

CatLuBooks отвечает на вопросы **по вашим книгам и файлам**. Вы загружаете
документы, задаёте вопрос — получаете ответ со ссылками на источники
(файл, страница, конкретный фрагмент).

Устройство простыми словами:

```
книга (PDF, EPUB, TXT, FB2) → текст → фрагменты → векторы → база (ChromaDB)
                                                  ↓
вопрос → поиск (смысл + точные совпадения) → отрывки → LLM → ответ со ссылками
```

Ключевые слова, которые дальше встречаются:

| Слово | Что это |
|---|---|
| **Агент** | отдельная «полка знаний»: свои книги, своя база, свой промпт. Агентов может быть сколько угодно, они не мешают друг другу |
| **Книга** | любой файл из `agents/<агент>/books/` — PDF, EPUB, TXT, MD, FB2 |
| **Фрагмент** | кусок текста (~1000 знаков) с адресом: файл и страница |
| **Индексация** | чтение книг и закладывание фрагментов в базу. Делается один раз |
| **Источник** | конкретный найденный фрагмент; в ответе он помечен `[1]`, `[2]`, … |
| **Промпт** | инструкция агенту, как отвечать. У каждого агента своя |
| **LLM** | модель, которая пишет текст ответа (Ollama, llama.cpp, облако) |

Важно: поиск и эмбеддинги работают **на вашем компьютере**, в облако уходит
только найденный контекст (если выбрать облачного провайдера для LLM).

## 2. Что нужно на компьютере

| Что | Зачем | Обязательно? |
|---|---|---|
| Python 3.10+ | запускает сервер | да (или поставьте `uv` — он скачает Python сам) |
| ~4 ГБ свободного места | зависимости, модели, база | да |
| Ollama + модель генерации | отвечает на вопросы на этом же ПК | желательно |
| Ключ облачного провайдера | если ответы делает облако | по желанию |
| Tesseract с русским языком | если есть сканы (PDF из изображений) | только для сканов |

Интернет нужен один раз: скачать зависимости и модель эмбеддингов (~120 МБ).
Дальше всё работает локально.

## 3. Установка за 10 минут

```bash
git clone https://github.com/Maksimasz/CatLuBooks.git
cd CatLuBooks
```

Ставим зависимости. Проще всего через [uv](https://docs.astral.sh/uv/) — он сам
скачает нужный Python и не требует активировать окружение:

```bash
# Windows: если uv ещё нет
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
# Linux/macOS: curl -LsSf https://astral.sh/uv/install.sh | sh

uv venv --python 3.12
uv pip install -r requirements.txt
```

Если uv не хочется — обычный `venv`:

```bash
python -m venv .venv
.\.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Запускаем сервер:

```bash
uv run python app.py              # или: python app.py
```

Откройте <http://localhost:8000>. В консоли появится адрес для телефона
(например `http://192.168.4.76:8000`) — он пригодится на шаге 12.

Проверить, что всё установилось:

```bash
uv run python -m unittest discover -s tests -t .
```

Тесты автономные: ни моделей, ни Ollama не требуют, занимают несколько
секунд.

## 4. Первый запуск: выбрать модель

Нажмите **⚙** в правом верхнем углу → вкладка **«Модели»**.

Там два поля: **Провайдер** и **Модель**, кнопка **«🔑 Ввести API-ключ»** и
**«↻ Обновить список»**.

### Вариант А. Всё локально (Ollama)

1. Установите [Ollama](https://ollama.com/download) и скачайте модель:
   ```bash
   ollama pull qwen2.5:3b        # лёгкая, идёт даже на слабом ноутбуке
   ```
2. В поле «Провайдер» выберите `ollama`, в поле «Модель» — нужную.
3. Ключ не нужен.

### Вариант Б. Локально, но через llama.cpp

См. [шаг 11](#11-своя-модель-llamacpp) — там же кнопка «Запустить».

### Вариант В. Облако

1. Получите бесплатный ключ, например у [Groq](https://console.groq.com/keys)
   или [Google AI Studio](https://aistudio.google.com/app/apikey).
2. **«🔑 Ввести API-ключ»** → выберите провайдера → вставьте ключ.
3. Нажмите **«↻ Обновить список»** — провайдер отдаст свои модели.

Ключ сохраняется только на этом компьютере (файл `secrets.json`) и в браузер
больше не возвращается. Список моделей обновляется раз в 5 минут; кнопка
«↻ Обновить список» обходит этот кэш.

### Что выбрать, если сомневаетесь

| Модель | Когда подходит |
|---|---|
| `qwen2.5:3b`, `gemma2:2b`, `llama3.2:3b` | Слабый ПК, ответы нужны быстро, качество — «просто чтение» |
| Модель 7–8B (например `qwen2.5:7b`) | Средний ПК, заметно лучше работает с терминами и таблицами |
| Groq / Gemini (облако) | Хотите качество и не хотите грузить свой ПК. Минус: нужен интернет и ключ |

Проверить, что модель отвечает: просто задайте вопрос в чате. Если вместо
ответа пришла ошибка — загляните в [раздел 19](#19-если-что-то-не-работает).

## 5. Создать агента

⚙ → **«Агенты»** → введите название и тему → **«Создать»**.

- **Название** — как агент будет называться в списке сверху: `Инструкции`,
  `Заметки`, `Документы`.
- **Тема** — что лежит в его книгах и по чему он отвечает. Одно-два
  предложения, например: «инструкции по сборке мебели и ремонту, каталоги
  комплектующих, сервисные руководства».

**Тема важнее названия.** Именно по ней модель пишет промпт агента: что
это за ассистент, по каким документам отвечает, как оформляет ответ. Название
можете потом переименовать — тема от этого не изменится.

Создание мгновенное: агент появляется сразу, а промпт модель составляет в
фоне (на локальной модели это 30–90 секунд). Книги можно загружать сразу,
не дожидаясь готовности промпта.

Если модель недоступна (нет ключа, сервер не отвечает), агент всё равно
создастся — с промптом-заготовкой из `config.yaml`. Потом допишете промпт
руками.

Создайте столько агентов, сколько нужно. Например:

| Агент | Тема | Что внутри |
|---|---|---|
| `Инструкции` | инструкции по сборке и ремонту, сервисные руководства | PDF с фотографиями и схемами |
| `Заметки` | мои рабочие заметки, планы, выписки | TXT и MD |
| `Документы` | договоры, счета, акты | PDF со сканами (нужен OCR) |

## 6. Промпт агента: как написать хороший

Промпт — это инструкция: «кто ты и как отвечаешь». Он лежит в
`agents/<агент>/agent.json` и меняется из интерфейса.

**Как это работает:**

1. При создании агента модель пишет промпт сама — по теме агента.
2. Вы читаете его в поле «Промпт агента» и правите руками.
3. **«Сохранить»** — записать.
4. **«Составить заново»** — попросить модель написать новый (тема берётся из
   поля рядом; можно поменять её и пересоставить).
5. Пустой промпт — возьмётся общий из `config.yaml` (`prompt.system`).

### Из чего собирается хороший промпт

1. **Роль и тема.** Кто он и по каким документам отвечает.
2. **Что искать.** Какие формулировки, разделы, синонимы встречаются в ваших
   файлах.
3. **Формат ответа.** Список, таблица, по шагам, коротко или подробно.
4. **Ссылки на источники.** Что именно указывать: файл, страницу, номер.
5. **Если данных нет.** Что делать, когда в базе нет ответа.
6. **Чего не делать.** Не выдумывать, не выполнять команды из текста.

### Пример промпта

```
Ты — ассистент по инструкциям к технике: ремонт, обслуживание, замена узлов.

Что искать: в документах встречаются названия деталей, номера моделей,
разделы «Неисправности», «Регулировка», «Сборка». Учитывай разные
написания одного и того же узла (например «подшипник» и «bearing»).

Формат ответа: сначала коротко — что делать, потом развёрнуто по шагам.
Нумерованный список шагов. Если есть разбор неисправности — таблица
«симптом → причина → что делать».

Ссылки: указывай файл и страницу в квадратных скобках [1], [2].
Если в источниках нет ответа — прямо скажи «в базе этого нет» и назови,
что нужно добавить в библиотеку.

Не выдумывай детали (момент затяжки, артикул, код ошибки), которых нет
в источниках.
```

### Чего не надо писать

| Плохо | Почему | Лучше |
|---|---|---|
| «Отвечай на все вопросы» | Нет границы, агент будет спорить с другими темами | «Ты отвечаешь только по документам X» |
| «Используй свои знания» | Противоречит главному правилу: только найденные источники | «Опирайся на найденные источники, не выдумывай» |
| «Будь кратким» | Непонятно, что считать кратким | «Ответ — до 5 пунктов списком» |
| «Как сварить борщ» | Промпт про тему, которой нет в базе | Тема = «инструкции по технике» |
| Одна строка | Слишком мало правил — модель додумает своё | 5–10 строк с ролью, форматом и ссылками |

### Подсказки

- Пишите по-русски, модели так понимают лучше.
- Проверка: задайте вопрос и посмотрите, устраивает ли формат ответа. Если
  нет — поправьте промпт, это быстрее, чем переиндексация.
- Промпт не влияет на поиск: он только влияет на то, как модель читает
  найденное. Если модель «не понимает вопрос», дело не в промпте, а в том,
  что такого текста нет в книгах.
- Разные темы — разные агенты, а не один агент со всеми промптами.

## 7. Книги: загрузка и индексация

⚙ → **«Книги»** (вкладка работает для выбранного агента — переключите агент
сверху, если нужно).

1. **«Загрузить книги»** — выберите файлы (можно несколько сразу).
   Поддерживаются `PDF`, `EPUB`, `TXT`, `MD`, `FB2`.
2. **«Индексировать»** — приложение прочитает файлы и разложит фрагменты по
   базе. Это занимает от секунд до нескольких минут (зависит от объёма).
   Работа идёт в фоне: окно настроек можно закрыть, а чатом — пользоваться.
   Прогресс виден во вкладке «Книги»: «Читаю книгу 2 из 7: имя.pdf» и полоска,
   а в конце — «Готово: в базе 17444 фрагментов, прочитано книг: 3».
3. **«Всё заново»** — перечитать все книги с нуля, даже уже готовые.
   Нужно, если вы поменяли настройки (например, включили OCR) и хотите, чтобы
   текст был разобран заново.

Что важно знать:

- Повторная индексация **не трогает** уже готовые книги: если файл не
  менялся (тот же размер и дата), он пропускается.
- Файлы можно загружать повторно — старый заменится новым.
- Книга в подпапке появится как `подпапка/файл.pdf`.
- Удаление: кнопка **🗑** у книги. Спрашивает, что удалять:
  - **только файл** — книга исчезнет из списка, но её фрагменты останутся в
    базе (в ответе такой источник будет помечен «нет файла»);
  - **файл и фрагменты** — удаляется всё (обычный вариант).
- «Индексировать» можно нажимать сколько угодно — лишнего не сделает.

## 8. Сканы и OCR

Если PDF — это фотографии страниц (скан), текста в нём нет, и поиск по нему
ничего не найдёт. Такой файл в списке помечен как «нужен OCR».

Что сделать:

1. ⚙ → **«Книги»** → переключатель **«Распознавать сканы (OCR)»**.
2. Если Tesseract не установлен, интерфейс покажет ссылку на установщик
   (на Windows — [UB-Mannheim](https://github.com/UB-Mannheim/tesseract/wiki),
   не забудьте русский язык). После установки **перезапустите сервер**
   (⚙ → «Сервер» → «Перезапустить»).
3. Нажмите **«Всё заново»** — сканы будут распознаны и переиндексированы.

Распознавание медленное: страница — доли секунды, книга на 300 страниц —
минуты. Включайте OCR только если действительно есть сканы: на обычных
PDF он просто добавляет лишний шаг.

## 9. Вопросы и ответы

Пишите вопрос в поле внизу, **➤** или Enter — ответ придёт в чат.

Как писать вопросы:

- **Конкретнее — лучше.** «Как настроить резервное копирование по расписанию»
  лучше, чем «про копирование».
- **Используйте термины из своих документов** — так шансов найти больше.
- **Уточняйте, если ответ не тот.** Спросите: «а в разделе про замену фильтра?».
  История вопросов сохраняется, поэтому можно вернуться к любому диалогу.
- **Помните про агенты**: вопрос попадёт в базу того агента, который выбран
  сверху. Переключили агент — поменялся контекст.

Что вы увидите:

- **Ответ** — обычный текст с разметкой (заголовки, списки, таблицы).
- **Ссылки `[1]`, `[2]`** в тексте — номера источников.
- **Панель «Источники»** справа (кнопка «Источники» в шапке) — список
  найденных фрагментов: файл, страница, начало цитаты. Нажали — открыли
  источник.
- **История** сохраняется автоматически: ⚙ → «История».

Если ответа нет:

- «В базе этого агента не найдено фрагментов» — в базе нет ничего похожего:
  загрузите нужные книги или переформулируйте вопрос.
- «Не нашлось подходящих фрагментов» — источники есть, но они не про то.
  Попробуйте другие слова.
- Модель ответила «в источниках нет ответа» — так и есть: данных не хватает.

## 10. Сведение ответов из разных книг

Один и тот же вопрос часто описан в нескольких книгах. По умолчанию модель
видит несколько отрывков и может склеить их в кашу. Переключатель
**«Сводить ответы из разных книг»** (⚙ → «Книги») меняет это:

| Режим | Что происходит | Когда включать |
|---|---|---|
| **Выкл** | Как было: модель отвечает по найденным отрывкам | Один источник, нужна скорость |
| **Быстро** | Один проход: модель сама сводит отрывки в один связный ответ | Обычный выбор |
| **Точно** | Два прохода: сначала черновик, потом ответ по нему | Разные версии одного и того же, важно не потерять детали |

Режим «Точно» заметно медленнее (две генерации) и тратит больше токенов.
Переключатель запоминается в `settings.json` и переживает перезапуск.

## 11. Своя модель: llama.cpp

Если хотите запускать модель через [llama.cpp](https://github.com/ggml-org/llama.cpp)
— консоль не нужна, всё делается из интерфейса.

1. Скачайте `llama-server.exe` со страницы
   [релизов llama.cpp](https://github.com/ggml-org/llama.cpp/releases) и
   положите его в папку `llama.cpp/` рядом с проектом (или оставьте
   в `PATH` — приложение найдёт и там).
2. Скачайте модель в формате `.gguf`
   ([Hugging Face](https://huggingface.co/models?library=gguf)) и положите файл
   в папку `models/` рядом с проектом. Подпапки тоже подходят.
3. ⚙ → **«Модели»** → блок **«llama.cpp — своя модель, без консоли»**:
   выберите модель в списке и нажмите **«Запустить»**.

Что произойдёт:

- сервер поднимется на `127.0.0.1:8080` (пока грузится модель — надпись
  «загружает модель…»);
- провайдер `llama.cpp` станет активным, а выбранная модель — текущей;
- можно сразу спрашивать.

Кнопка **«Остановить»** выключает сервер, **«Лог llama-server»** показывает,
почему модель не поднялась. Сервер не привязан к приложению: перезапуск
CatLuBooks его не убьёт.

Настройки — `config.yaml` → `llamacpp`:

```yaml
llamacpp:
  binary: ""        # пусто — ищем рядом с проектом и в PATH
  models_dir: "./models"
  port: 8080        # порт сервера; провайдер смотрит туда же
  args: ["-c", "8192"]   # ключи llama-server, например "-ngl", "99" для GPU
```

Если порт 8080 занят другой программой — приложение скажет об этом; тогда
укажите другой порт в `llamacpp.port` и перезапустите сервер.

## 12. Телефон: PWA

Сервер слушает `0.0.0.0`, поэтому доступен по локальной сети.

1. На ПК откройте **⚙ → «Сервер»** — там адрес для телефона, например
   `http://192.168.4.76:8000`.
2. На телефоне (в той же Wi-Fi-сети) откройте этот адрес.
3. В меню браузера выберите «Установить приложение» / «На экран „Домой“».
   Появится иконка — приложение открывается без адресной строки.

Если телефон не подключается:

- телефон и ПК должны быть в одной сети (не «гостевой» Wi-Fi);
- Windows может блокировать Python в брандмауэре — разрешите доступ для
  частных сетей при первом запуске;
- адрес может смениться при переподключении к сети — посмотрите новый в
  ⚙ → «Сервер».

## 13. Сервер: адреса, перезапуск, остановка

⚙ → **«Сервер»**:

- **Адрес для телефона** — ссылка, которую нужно открыть с телефона;
- **«Перезапустить»** — после правки `config.yaml`, `git pull` или установки
  Tesseract. Страница сама перезагрузится, когда сервер поднимется;
- **«Остановить»** — выключить сервер на ночь. Запустить обратно из браузера
  нельзя: понадобится команда в консоли.

Перезапуск занимает 15–30 секунд (модель эмбеддингов загружается заново) —
это нормально.

## 14. История вопросов

⚙ → **«История»»: каждый вопрос и ответ сохраняются автоматически (до 200
записей). Нажмите на запись — развернётся полный ответ с источниками.
Кнопка **🗑** удаляет ненужное, **«Очистить историю»** — всё сразу.

История лежит в `agents/<агент>/history.json` — её можно скопировать в
резервную копию вместе с агентом.

## 15. Управление агентом

⚙ → **«База»**:

- **«Переименовать»** — новое имя агента (папка и база остаются прежними);
- **«Очистить базу»** — удалить все фрагменты агента, книги на диске
  останутся. После этого база соберётся заново при следующей индексации;
- **«Удалить агента»** — стирает папку целиком: книги, базу, промпт,
  историю. Отменить нельзя.

В списке агентов (⚙ → «Агенты») у каждого есть кнопки: **✓** — сделать
активным, **✎** — переименовать, **🗑** — удалить.

## 16. Что где лежит на диске

```
CatLuBooks/
├── config.yaml          # все настройки (в git)
├── settings.json        # выбор из интерфейса: OCR, сведение (не в git)
├── secrets.json         # API-ключи провайдеров (не в git)
├── agents/              # агенты (не в git)
│   └── <агент>/
│       ├── agent.json   # название, тема, промпт
│       ├── books/       # загруженные книги
│       ├── db/          # база (ChromaDB)
│       └── history.json # история вопросов
├── models/              # GGUF-модели для llama.cpp (не в git)
├── logs/                # журналы сервера (не в git)
└── .venv/               # окружение Python (не в git)
```

Папка `agents/` — это ваши данные. Всё остальное можно удалить и скачать
заново.

## 17. Резервная копия и перенос

Чтобы перенести всё на другой компьютер, скопируйте:

1. папку `agents/` — агенты, книги, базы, промпты, история;
2. `secrets.json` — если хотите сохранить ключи (опционально);
3. `settings.json` — выбор из интерфейса (опционально);
4. `config.yaml` — если меняли настройки (но проверьте пути).

На новом компьютере: поставить зависимости, положить папки на место, запустить
`python app.py`. Переиндексировать ничего не нужно — база уже готова.

Подробности — в [README](../README.md#перенос-на-другой-компьютер-migration).

## 18. Настройки `config.yaml`

Файл лежит в корне проекта, меняется только руками. После правки — ⚙ →
«Сервер» → «Перезапустить».

| Раздел | Что настраивает |
|---|---|
| `prompt` | Промпт по умолчанию, задание модели на составление промпта, шаблоны ответов и сведения |
| `store` | Папка агентов, форматы книг, размер фрагментов, OCR |
| `embeddings` | Модель эмбеддингов (поиск) |
| `llm` | Провайдер, модель, температура, таймауты, лимиты токенов |
| `llamacpp` | Свой llama-server: путь, папка с GGUF, порт, ключи запуска |
| `search` | Сколько фрагментов искать, лимит контекста, режим поиска, сведение |
| `server` | Адрес и порт веб-сервера |

Что обычно правят:

- `llm.provider` и `llm.model` — модель по умолчанию (но в интерфейсе это
  делается проще);
- `search.n_results` и `search.max_context_chars` — сколько контекста уходит
  в модель. Если модель ругается «контекст не влезает», уменьшите
  `max_context_chars`;
- `llamacpp.args` — `-ngl 99` (GPU), `-c 16384` (длинный контекст).

## 19. Если что-то не работает

**«Модель ответила ошибкой 400» / «Сервер не отвечает — проверьте, запущен ли он»**
Провайдер не отвечает. Проверьте: Ollama запущен? `ollama list` показывает
нужную модель? Для облака — есть ключ? Нажмите «↻ Обновить список».

**«Контекст не помещается в модель»**
Модель маленькая. Уменьшите `search.max_context_chars` (например, до 6000) или
возьмите модель побольше, либо увеличьте `-c` в `llamacpp.args`.

**Ответы есть, но не про то**
Проверьте, что выбран нужный агент, и переформулируйте вопрос терминами из
книг. Если темы нет в базе — промпт не поможет, нужны файлы.

**PDF ничего не находит**
Скорее всего, это скан. Включите OCR (шаг 8) и нажмите «Всё заново».

**Индексация идёт очень долго**
Обычно это много страниц или сканы с OCR. Прогресс виден во вкладке «Книги»
(«Читаю книгу 2 из 7: имя.pdf» и полоска); дождитесь, не закрывая
приложение.

**После `git pull` ничего не изменилось**
Перезапустите сервер: ⚙ → «Сервер» → «Перезапустить». И сделайте Ctrl+F5 в
браузере — иначе покажется старая версия интерфейса из кэша.

**Телефон не видит сервер**
См. шаг 12: одна сеть, разрешение брандмауэра, свежий адрес из ⚙ → «Сервер».

**Интерфейс «поехал» (кнопки не работают, старый вид)**
Ctrl+F5 — обновить с жёсткой перезагрузкой.

## 20. Частые вопросы

**Можно ли спросить на другом языке?**
Да, вопросы и ответы работают на любом языке. Промпт лучше писать по-русски:
так модель ведёт себя предсказуемее.

**Загруженные книги куда-то делись?**
Они лежат в `agents/<агент>/books/`. Проверьте, что открыт нужный агент —
у каждого свои книги.

**Можно ли задать один агент на две темы?**
Можно, но лучше не надо: поиск смешивает темы, и ответы становятся менее
точными. Два агента лучше одного.

**Нужно ли заново индексировать после смены модели?**
Нет. База не зависит от модели генерации: индексы и эмбеддинги — отдельно,
ответы — отдельно.

**Что занимает место?**
База агента (папка `agents/<агент>/db/`), загруженные книги и модели в
`models/`. Размер виден в списке агентов.

**Как вернуть общий промпт?**
Очистите поле «Промпт агента» и нажмите «Сохранить» — агент снова возьмёт
промпт из `config.yaml`.

**Можно ли отключить интернет?**
Да, после установки зависимостей и модели эмбеддингов. Локальный провайдер
(Ollama или llama.cpp) работает без сети; облачный — нет.
